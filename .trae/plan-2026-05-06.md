# 2026-05-06 开发计划：资源下载系统彻底重塑

## 1. 核心目标
解决下载进度回跳、UI 报负面错误、404 资源无效重试以及下载速度极慢的问题。

## 2. 架构重写指令 (DownloadService.ts)
- **锁定静态分母**：初始化时计算一次 `GLOBAL_TOTAL_SIZE`，严禁动态修改。
- **进度只增不减**：使用 `Math.max(lastProgress, currentProgress)` 逻辑，进度条严禁后退。
- **纯增量下载**：启动前扫描磁盘，若文件存在且大小匹配，直接标记成功，严禁使用 `unlink` 删除已下载的文件。
- **静默重试机制**：移除 UI 上的失败计数。只要重试次数未用完，后台静默将任务重新入队，UI 保持平滑推进。
- **降低并发频率**：设置并发数为 2-3，优先使用 jsDelivr CDN，移除不可用的腾讯云 404 源。

## 3. UI 视觉净化指令 (ResourceDownloadScreen.tsx)
- **物理删除文件名**：严禁在 UI 显示 `nature_ocean` 等文件名或 `[object Object]`。
- **物理删除错误提示**：严禁显示"X个文件下载失败"等破坏治愈感的文字。
- **文案感性化**：统一显示为"正在为您开启疗愈之旅..."。
- **性能优化**：将进度更新频率改为 1000ms 一次，减少 Bridge 通信压力。

## 4. 资源路径修正
- 移除 `audioAssets.ts` 中失效的腾讯云 IP 源。
- 确保所有 GitHub 镜像链接后缀格式统一，正确处理路径中的 `%20` 转义。

---
请根据以上计划，将项目中的下载逻辑推倒重来。明天我们要的是一个"高级、稳定、只进不退"的资源同步系统。
