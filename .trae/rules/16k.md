📜 Android 16k 适配 & RN 0.81.5兼容准则
1. 核心架构保护 (No Delete Policy)
严禁删除核心类：无论遇到什么 SoLoader 报错，严禁通过删除 ReactNativeFeatureFlags 及其关联 Accessor 类来解决。

降级而非切除：如果 Native 库加载失败，统一采用“Java 降级方案”，即强制指向 ReactNativeFeatureFlagsLocalAccessor，禁止移除整个模块引用。

2. 补丁持久化规则 (Patch-Package First)
先 Patch 后编译：所有对 node_modules 的修改（特别是针对 16k 的 try-catch 或 accessor 修改），必须在修改后立即执行 npx patch-package react-native。

禁止覆盖：在执行 npm install 后，必须检查 Patch 是否依然生效，防止 16k 适配逻辑被官方源码覆盖。

3. 构建链路硬约束 (Build Pipeline)
对齐参数锁定：zipalign 必须且只能使用 -P 16 -f 4。

R8 保留规则：在 proguard-rules.pro 中必须显式保留所有 com.facebook.react.internal.featureflags.** 类，防止 R8 误认为这些“降级”后的类未被使用而将其剔除。

4. 16k 专项测试标准 (Validation)
安装前必检查：每次 adb install 之前，必须确认生成的 APK 经过了 zipalign -c -P 16 -v 4 验证。

闪退排查顺序：若启动闪退，优先检查 logcat 中是否有 lib*.so 加载异常，严禁盲目修改业务层 React 代码。
